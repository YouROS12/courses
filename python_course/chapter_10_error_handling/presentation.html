Error Handling - Making Programs Robust

When Things Go Wrong (And They Will!)

Why Error Handling Matters

Errors are inevitable - but crashes are optional!

Without Error Handling:

  • ❌ Programs crash unexpectedly
  • ❌ Users see scary error messages
  • ❌ Data might be lost
  • ❌ No way to recover

With Error Handling:

  • ✓ Programs handle problems gracefully
  • ✓ Users see helpful messages
  • ✓ Data is protected
  • ✓ Program can recover and continue!

Common Errors You've Seen:

🔢 Dividing by zero
📁 File not found
🔤 Invalid type conversion
📊 Index out of range

Common Exception Types

ValueError

Invalid value for conversion

int("hello") → ValueError

TypeError

Wrong type for operation

"5" + 3 → TypeError

ZeroDivisionError

Division by zero

10 / 0 → ZeroDivisionError

FileNotFoundError

File doesn't exist

open("missing.txt") → Error

IndexError

List index out of range

list[999] → IndexError

KeyError

Dictionary key not found

dict["missing"] → KeyError

Try-Except Blocks

The try-except block catches errors and handles them gracefully!

Without Try-Except (Crashes):

age = int(input("Enter age: ")) # User types "abc"
print(f"Age: {age}")
# ValueError: invalid literal for int()
# Program CRASHES!

With Try-Except (Handles Error):

try:
age = int(input("Enter age: "))
print(f"Age: {age}")
except ValueError:
print("Please enter a valid number!")
# Program continues running!

Multiple Except Blocks

Handle different errors differently!

try:
number = int(input("Enter number: "))
result = 100 / number
print(f"Result: {result}")
except ValueError:
print("That's not a valid number!")
except ZeroDivisionError:
print("Cannot divide by zero!")

Each Error Gets Custom Message!

  • ✓ User types "abc" → ValueError caught
  • ✓ User types "0" → ZeroDivisionError caught
  • ✓ User types "5" → Success!

The else Clause

The else block runs only if NO exception occurred!

try:
age = int(input("Enter age: "))
except ValueError:
print("Invalid input!")
else:
# This runs ONLY if no error occurred
print(f"Great! You're {age} years old.")
print("Data saved successfully!")

If Error Occurs:

❌ Try block stops
✓ Except block runs
❌ Else block skipped

If No Error:

✓ Try block completes
❌ Except block skipped
✓ Else block runs

The finally Clause

The finally block ALWAYS runs - error or not!

try:
file = open("data.txt", "r")
data = file.read()
process_data(data)
except FileNotFoundError:
print("File not found!")
finally:
# This ALWAYS runs!
print("Cleaning up resources...")

Perfect For:

✓ Closing files
✓ Releasing locks
✓ Cleanup operations
✓ Logging

Raising Exceptions

You can raise your own exceptions when something is wrong!

Basic Syntax:

def calculate_discount(price, discount_percent):
if discount_percent < 0 or discount_percent > 100:
raise ValueError("Discount must be 0-100")
discount = price * (discount_percent / 100)
return price - discount

Valid Input:

result = calculate_discount(
100, 20)
# Returns: 80.0

Invalid Input:

result = calculate_discount(
100, 150)
# ValueError raised!

Best Practices for Error Handling

✓ DO: Catch Specific Exceptions

except ValueError: # Good!

✗ DON'T: Use Bare Except

except: # Too broad!

✓ DO: Provide Helpful Messages

print("Please enter a number between 1 and 100")

✓ DO: Handle Errors Close to Source

Catch errors where they happen, not far away!

⚠ CAREFUL: Don't Hide Important Errors

Some errors should crash the program!

When to Use Error Handling

✓ Use Try-Except For:

  • 📝 User input validation
  • 📁 File operations
  • 🌐 Network requests
  • 🔄 Type conversions
  • 📊 Dictionary/list access
  • 🔢 Math operations (division)

When NOT to Use:

  • ✗ Don't replace normal logic
  • ✗ Don't catch bugs (fix them!)
  • ✗ Don't hide problems

Remember:

Error handling makes your program robust, not perfect!
